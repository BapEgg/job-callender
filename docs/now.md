## 최신 변경 — 예전 시안보다 우선
1. Slack: 갱신 요약 + 접수 마감 D-1/당일만. D-3·면접·과제·회신·생성 완료 알림은 없음.
2. Slack 링크는 휴대폰에서 열리는 채용 원문 URL. 로컬 준비실 URL이 주 링크가 아님.
3. 기존 공고는 저장된 마감으로 상태를 계산. 매일 모든 원문 AI 재검색을 요구하지 않음.
4. PC가 꺼진 날을 지나 복귀하면 현재 기준 미실행 배치 1회. 과거 날짜별 반복 실행 금지.
5. 회사별 질문 생성의 근거는 사용자 확정 제출본. 새 초안이 자동 제출본이 되지 않음.

## 다음 작업 하나: M0 착수 확인 및 첫 연결 설계
아래 순서로 한 작업을 준비한다.
- 저장소/기존 지시/변경 상태와 이 네 문서를 읽는다.
- 실제 시안의 화면과 토큰을 확인하고 라우트 목록을 맞춘다.
- 호스트 Windows에서 CLI 실행·로그인 재사용 가능 여부를 확인한다. 읽기 가능한 버전·help·상태를 우선하고 비밀 파일 내용을 출력하지 않는다.
- 기존 프로젝트 스택을 우선한다. 신규라면 Next.js/TypeScript 웹/API + PostgreSQL + host runner를 후보로 선택 근거와 함께 기록. ORM·버전은 임의 과거 지식으로 고정하지 않는다.
- 최소 테이블/작업 API/실행기 경계를 정하고 첫 작업 범위를 10줄 이내로 보고한다. 실제 데이터가 필요할 때 한 가지씩 요청한다.
- 비용·권한·설계 변경 문제가 없으면 M1 구현을 시작한다. 핵심 설계가 불명확하면 그 작업만 중단하고 질문한다.

| M3 | 매일/복귀 배치, 상태 계산, 제한된 Slack 요약·D-1·당일, 자동 시작과 실패 처리 | 미시작 |
